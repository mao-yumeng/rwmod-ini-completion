为什么需要它
Rusted Warfare 的 ini 是声明式且全有或全无的：整个模组有几百个文件，只要其中一行有问题，游戏拒绝加载整个模组，而且报错只告诉你哪个文件哪一行，不告诉你"应该写什么"。
真实会遇到的四种硬失败：
你写的	游戏报的	正确做法
shoot_sound: laser_fire	Could not find sound:laser_fire	只用内置 30 个音效名，或 ROOT:sound/xxx.wav
[core] showEnergyBar: true	The key '[core]showEnergyBar' was not used	它属于 [graphics]
image: SHARED:icon_no_energy.png	加载失败	SHARED: 下必须真实存在
文件带 UTF-8 BOM	加载失败	保存为无 BOM
这些错误的共同点是：写的时候完全看不出来，只有重启游戏才知道。而官方没有任何 ini 文档，段与键的对应关系只能靠翻官方资源。
这个扩展把"翻资源"这一步做成了数据：扫描官方 132 个 ini，得出 227 个段名、538 个键、270 个键有官方取值表，然后在编辑器里递给你。
功能
位置	补什么
行首输入 [	227 种官方段名（core、turret_#、action_*、hiddenAction_* …）
段内输入键名	只补该段合法的键，按官方出现频率排序
键: 之后	枚举取值、音效名、贴图名、单位 id、effect 名
悬停键名	官方出现次数、可用段、可选值
悬停段名	该段的全部合法键
触发字符：[ : _ .。补全项全部带说明，展开即用。
示例
段内过滤：不会给你错的键
在 [graphics] 里输入 sh，只会出来 shadowOffsetX / shadowOffsetY：
[graphics]
sh          ← 补：shadowOffsetX, shadowOffsetY
            ✗ 不会出现 shoot_sound（它属于 [turret_N]，写错段会拒绝加载）
枚举取值：不用查文档
[movement]
movementType:       ← 补：AIR, HOVER, LAND, NONE, OVER_CLIFF, OVER_CLIFF_WATER, WATER
音效名：只给真实存在的
[turret_1]
shoot_sound:        ← 补：gun_fire, cannon_firing, large_gun_fire2 …
                       ROOT:sound/meow_rifle.wav（如果你传了 --mod）
贴图名：只给真实存在的
[graphics]
image:              ← 补：SHARED:light_50.png … + 当前目录下的所有 png
悬停看历史
把鼠标停在 shootDelay 上：
shootDelay · 官方出现 116 次
可用段：attack, turret_1, turret_2 …
安装
方式一：VSIX（推荐）
code --install-extension rwmod-ini-0.1.0.vsix
或在 VS Code 中：扩展 → 右上角 ... → 从 VSIX 安装，选文件，然后重启。
方式二：从源码装
把本仓库下载/克隆到本地后，进入 rwmod-ini 目录，将整个目录复制到扩展目录（Windows 为 %USERPROFILE%\.vscode\extensions\rwmod-ini-0.1.0\），重启 VS Code。
方式三：开发调试
code .
# 按 F5 —— 会打开一个加载了本扩展的新窗口
打包自己的 VSIX
npm run package     # 需要网络下载 @vscode/vsce
使用
装好后重启 VS Code，打开任意模组的 .ini，开始输入即可，无需配置。
只在 RW mod 的 ini 里生效
判定条件（满足任一）：
文件里有一个 [core] 段头
含 class: CustomUnitMetadata
含 displayText:
所以 git config、各类编辑器配置等普通 ini 不会被干扰。
命令
命令	作用
RW mod: 重新加载补全数据	改了 data/rwmod-lang.json 后不用重启，直接重载
数据从哪来
data/rwmod-lang.json 完全由脚本从游戏本体生成，没有一行是手写的：
内容	来源	规模
段名、键、键所属段	assets/**/*.ini	227 段 / 538 键
键的取值枚举	同上，按出现频率提取	270 个键有取值表
内置音效名、效应名、音效类键	game-lib.jar 常量池	30 / 16 / 10
共享贴图文件名	assets/units/shared/*.png	48
单位 id	官方 name: + 可选的模组目录	215
枚举是自动推断的：某个键在官方资源里出现过的取值种类在 2~24 之间、且都是短标识符，就当作枚举收进来。所以 movementType、displayType、image_shadow、class 这些都能自动补值。
重新生成数据
游戏更新后，用你自己的游戏目录重跑：
node scripts/gen-lang-data.js --assets "E:/Rusted/Rusted Warfare/assets"
想把某个模组自己的单位 id、自定义 effect、ROOT:sound/*.wav 也补进去：
node scripts/gen-lang-data.js \
  --assets "E:/Rusted/Rusted Warfare/assets" \
  --mod "F:/my-mod/MyFaction"
不传 --assets 时会自动尝试几个常见 Steam 安装路径。
重新生成后在编辑器里执行 RW mod: 重新加载补全数据，或重启 VS Code。
注意：scripts/builtin.json 里的音效名和效应名是从游戏 jar 常量池提取的，游戏大版本更新后可能需要重新导出。它和 assets/ 扫描是两套来源，互不依赖。
开发与测试
npm test     # 无头冒烟测试，18 项断言
npm run gen  # 重新生成 data/rwmod-lang.json
测试的做法：桩掉 vscode 模块，直接把补全函数拉出来跑断言。
const ext = require('../extension.js');
const items = ext.__test.keyItems(mkDoc('[graphics]\nimage: x.png\n'), pos, 'sh');
assert(!labels(items).includes('shoot_sound'));   // 段内过滤不能回退
extension.js 末尾的 __test 导出就是给测试用的，VS Code 运行时不会走那条路径。
数据完整性也在断言里（段数、core 键数、枚举键数），所以改了生成器导致数据缩水，测试会直接失败。
如果你用更新版本的游戏重新生成了数据，段/键数量可能正当变化，此时需同步更新 test/smoke.js 末尾那四个数字（227 / 142 / 270）。
设计取舍
为什么段名已知时只补该段的键
因为段位放错是硬失败：The key '[core]showEnergyBar' was not used 会让游戏拒绝加载整个模组。
补全的价值不只是"打字快"，更是"不会写出非法状态"。所以宁可少补几个键，也不给一个跨段但可能非法的选项。
只有当段名完全未知（你自己新造的段）时，才退回补全全部 538 个键。
为什么不做语法检查
已经有更严格的离线校验在承担这件事（段位合法性、引用存在性、BOM、音效名）。编辑器内做重复实现只会两边不一致。这个扩展专注在写的时候给对选项。
为什么不补表达式语言
Rusted Warfare 有内置的条件表达式（if self.hp(lessThan=1)、@define、${} 插值、随机函数等），词表只能从 game-lib.jar 的 class 常量池反推，官方无文档、语法未完全验证。补上去只会给错的建议，所以刻意不做。
已知限制
只做补全与悬停，不做错误检查
不补表达式语言（见上）
段名已知时严格不给跨段键 —— 如果某个跨段用法确实合法，悬停可以看到该键的「可用段」列表自行判断
数据基于当前游戏版本的 assets/；游戏大更新后需重新生成
只识别 .ini，不处理 .rwmod 压缩包内部
常见问题
Q：装好了但什么都不补？
确认三点：文件是 .ini；文件里有 [core] 或 displayText:；改完扩展后重启过 VS Code（或执行过重载命令）。
Q：补全项太多，想要的在最上面？
补全按官方出现频率排序，越常用越靠上。段内键优先于全局键。
Q：我在自己新建的段里，为什么补全了全部键？
因为该段在官方资源里不存在，无法判断合法性，所以退回全量列表——这时请自行确认。
Q：能补 CUSTOM: 开头的自定义 effect 吗？
能。只要生成数据时传了 --mod，你模组里的 [effect_xxx] 就会以 CUSTOM:xxx 的形式出现在 explodeEffect、spawnEffects 等键的补全里。

贡献
数据永远是"官方资源的镜像"，所以：
新增功能：欢迎提 PR，但请保证 npm test 通过
数据有错：大概率是 scripts/gen-lang-data.js 的提取逻辑问题，而不是 data/rwmod-lang.json 本身（那个文件是生成物，别手改）
游戏更新：跑一次 npm run gen 就会跟上
